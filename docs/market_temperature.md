# 市场温度与市场结构（v2.1）

## 页面三层
1. 综合市场温度：A股/美股独立计算，0–100。
2. 市场风格：大盘50%、中小盘25%、科技成长25%，只观察市场内部风格，不加入综合温度。
3. 七大产业热度：芯片半导体、数据中心、核能与电力、机器人制造、生物科技、太空经济、低空经济，按相对强度、趋势、动量排序。

## 综合温度算法
| 分项 | 权重 | A股 | 美股 |
|---|---:|---|---|
| 市场宽度 | 40% | Eastmoney全A上涨/下跌家数比例 | RSP/SPY、QQEW/QQQ等权相对市值加权表现（市场参与度代理） |
| 市场趋势 | 25% | 上证、深证、创业板、沪深300、中证500 | SPY、QQQ、IWM、DIA |
| 成交活跃度 | 15% | 沪深300ETF近20日均量的250日分位 | SPY近20日均量的250日分位 |
| 波动与风险 | 20% | 上证指数20日实现波动率历史分位反向计分 | VIX历史分位反向计分 |

缺失分项不补0或50；可用权重低于80%时总分为null。A股宽度日期使用行情报价时间戳，不借用趋势指数日期。美股不依赖Yahoo未确认可用的A-D线，改用RSP对SPY、QQEW对QQQ的60日等权/市值加权相对表现。两组都必须有220根日线并且日期同步，否则宽度分项缺失。

## 美股等权参与度与巨头权重影响
- RSP代表标普500等权，SPY代表标普500市值加权；QQEW代表纳斯达克100等权，QQQ代表纳斯达克100市值加权。
- 计算两组过去60个共同交易日的相对收益，分别映射为参与度分数并等权平均。两组都有效才输出美股宽度分项。
- 同时显示两组市值加权收益减等权收益的平均百分点差。正值表示市值加权指数领先（巨头权重影响更强）；负值表示等权指数领先（上涨参与面更广）。这是参与度代理，不冒充逐股涨跌家数统计。

## 市场风格代理
- A股：沪深300（大盘）、中证1000（中小盘）、科创50（科技成长）。
- 美股：SPY（大盘）、IWM（小盘）、QQQ（科技成长）。
- 风格分独立展示，不参与综合温度，避免重复计权。

## 产业热度
40%为过去60个共同交易日相对市场基准强度（A股沪深300/美股SPY）；35%为MA50/MA200趋势结构；25%为5日动量相对20日均速变化。至少220根日线，行情日期与基准差不超过5个自然日；相对收益只在共同交易日对齐。有效项目排序，缺失项目保留并显示原因。

## 存储与刷新
Supabase market_temperature_daily按(market,trade_date)幂等upsert，完整风格和产业快照保存在snapshot JSON。API缓存键升级v2，防止旧缓存覆盖新结构。每日Parquet冷备保留完整快照。交易时段仍使用上一完整收盘快照。方法版本2.1.0。温度标签不是买卖阈值。


## 服务隔离与冷备回退（v2.2）
- 温度计算只在后台线程运行，API 请求不等待实时行情计算。
- 进程内全局互斥锁保证同一时刻最多执行一个市场温度刷新，A股/美股切换不会并行拉取两套指数和产业行情。
- 刷新失败不覆盖内存中的最后有效快照；原看板、仓位、分析和其他行情 API 不依赖温度计算结果。
- 读取优先级：进程内快照 → Redis/Supabase缓存 → 冷备文件 → pending/数据不足。冷备读取放入线程并限制最多2.5秒。
- 每日归档在Parquet之外原子写入 `latest_cn.json` / `latest_us.json`，其中保存完整展示快照及对应Parquet路径。API故障时用JSON sidecar快速恢复显示，Parquet用于历史冷备。
- 冷备文件默认从 `https://raw.githubusercontent.com/sizhitu/Autopilot-data/main/data/market/temperature` 读取；私有数据仓需在Render配置 `MARKET_TEMPERATURE_COLD_BACKUP_TOKEN`（或复用 `DATA_REPO_TOKEN`）。也可将文件挂载到本地持久盘并配置 `MARKET_TEMPERATURE_COLD_BACKUP_DIR`（目录内放置 `latest_cn.json` 和 `latest_us.json`）。
- 冷备默认只接受14天内快照，可通过 `MARKET_TEMPERATURE_COLD_MAX_AGE_DAYS` 调整；回退后UI明确标记“冷备文件”，后台继续尝试恢复实时数据。
- 冷备文件缺失、损坏或远端超时只会让温度计显示数据暂不可用，不会抛出到其他业务接口。
