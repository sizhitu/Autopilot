# 订阅退费建议（SaaS 最佳实践）

目标：对诚实用户公平，降低「用完即退」套利，符合卡组织/支付平台规则。

## 推荐政策（可写在结账页 / 帮助）

1. **冷却期全额退**  
   首次订阅后 **24～72 小时内**，且几乎未使用核心功能 → 可申请全额退款。

2. **按比例 / 不退当月**  
   超过冷却期：  
   - 常见做法 A：当月不退，取消后续续费（cancel at period end）  
   - 常见做法 B：未使用天数按比例退（实现成本高，早期可不做）

3. **明显滥用不退**  
   短时间大量调用分析/导出后立即退款、反复「订阅→用→退」→ 拒绝退款并标记账号。

4. **退款后立即降级**  
   Webhook `refund.succeeded` → `plan=free`，立刻收回 Pro/Plus 权限（不要等账期结束）。

5. **取消 ≠ 退款**  
   「管理订阅 → 取消」= 到期不再扣款，**当前账期仍可用**。  
   退款 = 钱退回 + **立即**变免费。

## 流程建议

| 场景 | 处理 |
|------|------|
| 用户点取消续费 | cancel-order，状态 canceling → 到期 canceled，期间仍 Pro/Plus |
| 用户要退款 | 人工或支付平台退款 → webhook 降 free |
| 冷却期内首次退 | 尽量同意，提升信任、降低拒付（chargeback） |
| 拒付（chargeback） | 按 Waffo/卡组织流程应诉；账号冻结付费能力 |

## 产品侧可做的防护（可选后续）

- 记录开通时间、核心 API 调用次数，退款审核时参考  
- 同一支付指纹 / 邮箱限制「退款后再订阅」次数  
- 结账页展示明确退款文案，减少争议

早期用户少时：**宽冷却期 + 取消续费自助 + 退款人工处理** 通常最划算。
